# Proposal: fix-slug-rules

## Why

Правила slug нигде не специфицированы (P7 пула). Проверка premise по коду
(`internal/slug/slug.go`, 35 строк) показала: proposal прав в главном,
но врет в одном пункте.

**Живо:**
- `! ? # $ % &` и прочий мусор проходят в имена файлов как есть: `"Hello!"`
  дает `hello!.yaml`. На ext4 легально, в шелле больно (globbing, истории).
  Набор чистящихся символов - закрытый список из 12 замен, все остальное
  проходит.
- Длины нет вообще. Тайтл на 300 символов дает ошибку `file name too long`
  (ext4 NAME_MAX 255): путь к крашу из пользовательского ввода без единого
  теста на него. Два существующих теста (`TestSlug_UnlimitedLength`,
  `TestSlug_NoCollisionOnLongTitles`) утверждают отсутствие капа как желаемое
  поведение - они кодируют анти-спеку и должны быть переписаны.
- Коллизии (`"Hello World"` vs `"hello_world"`) обрабатываются везде отказом
  (server 409, CLI и MCP - явная ошибка до записи), но нигде не зафиксировано.

**Мертво:**
- `"..." дает скрытые файлы` - неправда. Точки превращаются в дефисы, дефисы
  по краям тримятся: `"..."` дает пустую строку и отклоняется. Точка вообще
  не может появиться в выводе, скрытый файл невозможен. Опасность не в точках,
  а в нечистящихся спецсимволах и длине.

## What Changes

Решение: allowlist вместо blocklist.

- `slug.Of`: идем по рунам. Unicode-буквы и цифры (кириллица сохраняется -
  это тестируемое поведение) - как есть в нижнем регистре; разделители
  (пробел, `_ / \ . : ,` и пр.) - в дефис; все остальное - выкинуть.
  Дефисы схлопнуть, по краям тримануть. Закрытый список замен удаляется как
  класс: новое правило покрывает все символы сразу, а не 12 штук.
- Max длина 200 байт (не рун: NAME_MAX считает байты, кириллица многобайтовая).
  Обрезка по границе UTF-8, висячий дефис на срезе тримится. 200 + `.yaml` =
  205 < 255 с запасом. Пустой результат после чистки - как раньше, ошибка
  `invalid title`.
- Коллизии: поведение не меняем, фиксируем. Одинаковый slug из разных тайтлов -
  отказ с конфликтом везде (409 в API, явная ошибка в CLI/MCP до записи), не
  слияние. Обрезка может столкнуть два длинных тайтла - это честный 409,
  спека так и говорит.
- Существующие ID не мигрируются. Старые файлы с `!` остаются лежать как были,
  читаются как раньше.

## Non-goals

- Транслитерацию кириллицы не вводим. `настроить-caddy` - валидный ID,
  файловая система его ест.
- Человекочитаемые суффиксы при коллизии (`-2`) не делаем. Отказ честнее:
  молчаливый суффикс прячет от пользователя, что его шаг лег не туда.
- Валидации в api/cli/mcp не дублируем: все уже идут через пакет, задача 1.3
  исходного плана фактически выполнена кодом. Остается сделать правильным
  сам `Of`.

## Impact

- Affected specs: `project-store` (ADDED: slug contract). Новую capability не
  заводим: slug - правило хранения ID, ему место рядом с остальным store.
- Affected code: `internal/slug/slug.go` (переписать `Of` на руны + кап),
  `internal/slug/slug_test.go` (граничные тесты; два теста про unlimited
  переписать - они утверждают противоположное).
- Соседи: baseline `project-store` про slug молчит - ADDED чисто.
  `serve-api:62` упоминает `(slug id, duplicate title yields 409)` мимоходом -
  не требование про формат, не трогаем, поведение совпадает.
- P7 пула закрывается архивом этого ченжа.
