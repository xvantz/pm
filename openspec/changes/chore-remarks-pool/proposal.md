# Proposal: chore-remarks-pool

## Why

При аудите PM накопились замечания разного веса: часть подтвержденные расхождения спеки с кодом, часть дизайн-критика, часть гэпы покрытия. Чтобы ничего не потерять и разбирать по одному, паркуем все в пул. Пул не архивируется оптом: каждый пункт либо уходит в свой ченж, либо закрывается как wontfix с причиной.

## What Changes

Ничего в коде. Только этот пул. Разбор пунктов по одному, по порядку.

## Impact

- Affected specs: нет (tooling/backlog change).
- Каждый пункт пула при принятии превращается в отдельный ченж с дельтой.
