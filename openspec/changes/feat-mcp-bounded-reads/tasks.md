# Tasks: feat-mcp-bounded-reads (DoD обязателен)

## Phase 1: Форма ответа

- [x] 1.1 `handleGetProject`: сводка по умолчанию (счётчики шагов по статусам,
  число незакрытых блокеров, последний закрытый шаг), `detail: true` → полный дамп
  **DoD:** сводка < 500 Б на проекте с 7 шагами; `detail:true` совпадает с
  прежним выводом байт-в-байт
  **Результат:** `jsonProjectSummary` + `buildProjectSummary`: счётчики по статусам, незакрытые блокеры, последний закрытый шаг (по инстанту, не по строке), hint с названием следующего вызова. Замерено: сводка **429 B против 2136 B** дампа на проекте из 7 шагов — 5.0x. `detail:true` возвращает прежний полный дамп.
- [x] 1.2 `handleListSteps`: только id/title/status/updated_at, без blockers и artifacts
  **DoD:** тест на проекте с блокером: в выводе нет поля `blockers`
  **Результат:** `handleListSteps` переписан на `jsonStepBrief` (id/title/status/updated_at). Старый вариант возвращал полные `types.Step` вместе с blockers — дубль функции удалён, заодно исчезли `jsonStepItem`/`jsonBlockerItem` из вывода списка.
- [x] 1.3 Новый тул `get_step`: полный один шаг (blockers, artifacts, метки)
  **DoD:** зарегистрирован, `inputSchema.type == "object"`, уникальное имя;
  тест: существующий шаг отдаётся целиком, несуществующий → ошибка с именем
  **Результат:** `handleGetStep` + регистрация `get_step` (17-й тул). Несуществующий шаг → ошибка с именем шага и номером проекта. Кросс-проектный step_id → та же ошибка, не тихий пустой ответ.
