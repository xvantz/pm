# Proposal: fix-event-time

## Why

`NowISO` (`internal/types/types.go:80`) пишет только дату: `2006-01-02`. Последствия:

1. **Порядок событий внутри дня теряется.** Все `UpdatedAt`, проставленные в один день, идентичны. Для системы долговременной памяти это слепота к intraday-истории: нельзя сказать, что было раньше — закрытие степов или блокер.
2. **Три тихих поломки в `internal/briefing`** после перехода на RFC3339 — не падают, а врут:
   - `briefing.go:281` `s.UpdatedAt == date` — сравнение с `"2026-09-29"`; на RFC3339 не сматчится никогда, `steps_today` уйдёт в 0 без ошибки;
   - `briefing.go:259` `s.UpdatedAt > lastDone.UpdatedAt` — строковое сравнение, валидно только пока формат дата;
   - `briefing.go:334` `parseDate` с константой `2006-01-02` — на RFC3339 вернёт zero time, и `blockerDaysAlive` (`:323`) молча вернёт 0: долгоживущие блокеры исчезнут из брифинга.
3. **Дубль по дням.** Шаг, тронутый сегодня, и шаг, тронутый вчера, неразличимы для подсчёта `steps_today`, если один из них тронут повторно.

Текущий suite не способен поймать ни одну из поломок: `internal/store/mock.go` сеет done-шаги **без `UpdatedAt`**, поэтому `countStepsOnDate` в mock всегда даёт 0 и ни один тест не проверяет `steps_today`.

Load-bearing момент: `feat-mcp-paging-briefing` (P11 пула) специфицирует брифинг с подсчётом `today/week`. Если спека ляжет на date-only, а RFC3339 придёт следом, дельту придётся переписывать.

## What Changes

- **Тип `types.Timestamp`** — обёртка над `time.Time` вместо голой `string` в `CreatedAt`/`UpdatedAt`/`Date`/`CompletedAt`. Нативный `time.Time` отпадает экспериментально: живые файлы PM содержат `updated_at: "2026-09-27"` (в кавычках), и yaml.v3 на таком значении падает `cannot parse "" as "T"`. Плюс `time.Time` не поддерживает `omitempty` — в YAML уходит мусор `0001-01-01T00:00:00Z`.
- **Формат записи — RFC3339 UTC с `Z`**, секунды, без дробной части. Обоснование экспериментом: строковая сортировка по меткам с `Z` даёт верную хронологию, с офсетами (`+03:00`) — нет. Тип всё равно запрещает строковое сравнение на уровне компилятора, но единый формат делает порядок предсказуемым и в отладочных выводах.
- **Чтение принимает обе формы.** Legacy `YYYY-MM-DD` = полночь UTC. Миграция данных — ручная, скриптом, отдельным обратимым коммитом (в репо под git); `pm doctor` показывает счётчик legacy-записей, но не чинит их сам: обход демона ради записи возвращает гонки, которые демон убрал.
- **Тонкие поломки становятся громкими.** Нечитаемая метка: `slog.Warn` с `project`/`step`/`field`/`raw` + запись в новое поле ответа `data_warnings`. Бриффинг не падает (одна битая метка не должна ронять сводку), но агент видит, что цифры неполные. Тихая подмена запрещена.
- **День брифинга = локальный день зоны демона**, а не UTC. Степ, закрытый в 01:00 MSK, попадает в сегодняшний брифинг, а не во вчерашний. Метки сравниваются как инстанты, режутся по календарному дню зоны демона. `pm briefing` и `get_briefing` обязаны считать через одну функцию, иначе терминал и MCP дадут разные числа.
- **Тест на intraday-регрессию** в этом же ченже: mock-шаги с двумя метками в одном дне + невалидная метка. Без него фикс недоказуем.
- Пробел покрытия в самом пуле (задача 1.1) закрывается этим же тестом.

## Non-goals

- Не трогаем `Briefing.Date` и query-параметр `date` в `get_briefing` — это «за какой день», а не событие. Имя поля `Decision.Date` в YAML сохраняется, меняется только значение.
- Не вводим `TZ` в конфиг брифинга: зона берётся у процесса, отдельно её не конфигурируем.
- Спека брифинга (`capability briefing`) едет в `feat-mcp-paging-briefing`; здесь фиксируем только формат меток и правило зоны.

## Impact

- Affected specs: `project-store` (ADDED: timestamp contract). Формулировка в старом proposal «MODIFIED: формат меток» была неверна — грепнуто: ни одна baseline-спека формат дат не фиксирует, а bulk close упоминает лишь «fresh `UpdatedAt`», что остаётся верным при любом формате. Поэтому ADDED, а не MODIFIED.
- Affected code: `internal/types/types.go` (Timestamp + NowISO), `internal/briefing/briefing.go` (парсер, сравнения, зона, `data_warnings`), `internal/store/mock.go` (метки в mock), тесты `briefing`/`store`/`domain`/`mcp`.
- Соседи для грепа перед финализацией дельты: `internal/api/server.go`, `internal/cli/{project,step,blocker,decision,del}.go`, `internal/mcp/tools.go`, `internal/store/{filestore,mock}.go`, `internal/domain/step.go` — все места, где метка пишется или сравнивается.
- Миграция данных отдельным коммитом в этом же ченже, до архива.
