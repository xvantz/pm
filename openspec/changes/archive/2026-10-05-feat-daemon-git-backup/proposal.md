# Proposal: feat-daemon-git-backup

## Why

PM-данные живут в одной папке на хосте (`/home/xvantz/Documents/pm`) без
версий и без копии вне хоста. Сдохший диск или случайный `rm` = потеря всех
проектов. Формат YAML гит-френдли, но процесса нет: в коде демона ноль
git-интеграции (единственные совпадения `sync` это fsync), папка на хосте
создана руками без автоматики.

Раз демона - единственный писатель, ему и владеть гитом: второй писатель
в репо исключен по построению.

## What Changes

- **Демон владеет git-состоянием папки данных**: на старте `init` если
  `.git` нет, усыновление если есть. `remote get-url origin` сверяется с
  ожидаемым из конфига; несовпадение - fail-closed (старт без пуша + громкий
  лог, никогда тихий пуш не туда).
- **Коммит на действие, на уровне API-хендлеров**: одно мутирующее действие =
  один коммит с message вида `add_step <proj> <slug>` / `close_project <id>`.
  Хуки в хендлерах, не в FileStore: иначе тач-коммиты дадут кашу.
  Порядок: YAML на диск -> коммит -> ответ. Упавший гит не роняет запись:
  warn в лог, следующий коммит подхватит (commit-all).
- **Пуш асинхронно с ретраями**: доступность демона не зависит от сети.
  Офлайн = копим локально, уедет позже. Очередь переживает рестарт
  (незапушенное видно по `git status` / счетчику ahead).
- **Nix-опции**: `services.pm.backup = { enable, repoUrl, keyFile }`.
  Ключ - файл 600 у сервис-юзера (та же конвенция что sops-секреты),
  в nix store и логи не попадает. Автор коммитов фиксированный (`pm-serve`).
- **Тесты**: коммит на запись во временном репо; пуш в локальный bare
  (file-remote, ключ не нужен); remote-mismatch роняет старт с пушем;
  инжектированная поломка гита не ломает ответ API.

## Non-goals

- Не восстанавливаем данные из бэкапа автоматом: restore это ручной
  `git checkout`, бэкап write-only.
- Не подписываем коммиты: приватный бэкап, подпись не дает ничего.
- Не коммитим на чтение: `list/get` историю не мусорят.
- Не увозим секреты: `.env`, токены и ключи в папке данных (если появятся)
  идут в `.gitignore` шаблон при init.

## Rollout (после мержа, не часть ченджа)

1. Создать приватный `xvantz/pm-data` на инстансе
2. Проверить write-доступ deploy-ключа: ручной пуш тестового коммита.
   Не взлетит - отдельный follow-up чендж на `tokenFile` (HTTPS-токен бота),
   код этого ченджа не трогаем
3. Включить в хост-конфиге (`services.pm.backup`), `nixos-rebuild switch`,
   создать тестовый проект через MCP и проверить коммит в `pm-data`

## Impact

- Affected specs: новая capability `store-git-backup` (ADDED: владение

- Affected code: новый `internal/store/gitbackup.go` (обертка),
  `internal/api/server.go` (хуки в мутирующих хендлерах),
  `flake.nix` (опции `services.pm.backup` + проброс в сервис),
  новые тесты.
