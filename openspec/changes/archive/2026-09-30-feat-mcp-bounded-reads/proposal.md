# Proposal: feat-mcp-bounded-reads

## Why

`get_project` возвращает `json.Marshal(pd)` — весь `ProjectData` без упаковки.
Измерено на фикстурах:

```
list_projects (все 6 проектов)     =  1755 B
get_project   (#1, 5 шагов)       =  2195 B
get_project   (#4, 6 шагов)       =  2222 B
компактная форма того же (#1)     =    53 B   → 41x меньше
```

Детальный объект одного проекта стоит **больше, чем список всех проектов**.
Это перевёрнутое соотношение: детальный просмотр должен стоить дороже обзора,
а не наоборот.

Масштаб: сейчас 7 шагов = 2.1 КБ. Импорт ченджа из OpenSpec (30+ шагов,
артефакты, решения) даёт 10–15 КБ на один вызов, и это уходит в контекст
агента.

Разбор «пагинация vs форма ответа»: для 2 КБ курсоры — оверинжиниринг,
прокручивать нечего. Проблема не в объёме, а в том, что агент, которому нужно
«посмотреть состояние проекта», получает все поля, которые не спрашивал.

## What Changes

Три уровня чтения вместо двух, потому что «кратко / полный дамп» не закрывает
вопрос «разобрать один шаг в проекте с 20 шагами» — детальный дамп всё равно
тащит все 20.

**Уровень 1 — `get_project` по умолчанию: сводка проекта.**
Номер, название, статус, цель, теги, счётчики шагов по статусам, число
незакрытых блокеров, последний закрытый шаг. Без списка шагов.
Ориентир: 200–400 Б.

**Уровень 2 — `list_steps`: список шагов кратко.**
`id`, `title`, `status`, `updated_at`. Сейчас возвращает полные `types.Step`
вместе с blockers и artifacts — то есть второй уровень частично есть, но
возвращает лишнее.

**Уровень 3 — `get_step` (новый тул): один шаг целиком.**
Всё про шаг: blockers, artifacts, метки времени. Ориентир: 300–600 Б.

Полный дамп `get_project` не удаляется: флаг `detail: true` возвращает прежнее
поведение. Так ничего не ломается для тех, кому нужен весь проект, а
подавляющее большинство вызовов становятся дешёвыми.

## Non-goals

- Не вводим курсоры и `offset`. Для объёмов, которые даёт PM, это лишнее.
- Не меняем HTTP API демона: `GET /api/projects/{ref}` остаётся полным для
  CLI и других клиентов. Форма ответа — свойство MCP-поверхности.
- Не обрезаем `goal` в сводке: он короткий и нужен для «что за проект».
- Не специфицируем формат вывода `list_projects` — отдельный вопрос, там
  свой предел по числу проектов.

## Impact

- Affected specs: `mcp-server` (MODIFIED: форма ответа `get_project`,
  ADDED: тул `get_step`).
- Affected code: `internal/mcp/tools.go` — хендлеры `handleGetProject`,
  `handleListSteps`, новый `handleGetStep`, регистрация тула, схемы.
- Пересечение: `internal/mcp/tools.go` делится с `feat-mcp-trash-restore`
  (регистрация новых тулов в том же слайсе `tools`). Правило 3 AGENTS.md:
  оба правят один файл, значит мердж последовательный. Этот мерджится первым,
  `trash-restore` ждёт — он тоже добавляет тулы и выигрывает от того, что
  каталог уже пересобран.
- Сосед по требованиям: `mcp-server` содержит требования про схемы тулов;
  грепнуть на `get_project`/`list_steps` перед merge.
